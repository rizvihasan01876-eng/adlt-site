SITE CONFIGURATION

Advertisement slots

Configure every placement with separate desktop/PC and mobile creatives. Visitors see only the version for their current device; changes save to Firebase and update the public site.

Adsterra setup

  • In Adsterra, add and verify your website, then create an ad unit for the placement you want. Copy the complete HTML/JavaScript code from that ad unit and paste it into the matching box below.
  • Use Adsterra Banner code for Top, Trending, After 12 videos, and Bottom placements. For the Video page slot below the player, you can use a Banner unit or the complete TSVideoShorts snippet; the snippet displays in that slot, not inside the movie stream.
  • Use Adsterra Social Bar code only in the Social Ads Bar box. Social Bar is an overlay format, not a regular banner.
  • A Smartlink/direct URL is not banner embed code; it only creates a clickable link. Create the appropriate Adsterra ad unit and paste its full code instead.
  • For each placement, paste the PC/desktop ad code in its Desktop box and the phone/tablet code in its Mobile box. They are selected automatically by screen width; leave a device box empty if you do not want an ad shown there.
  • Create separate Adsterra ad units for placements that need distinct creatives. Enable the placement checkbox and save.

Adsterra controls the delivered creative dimensions and whether an ad fills. Use its generated code unchanged; do not paste only part of the snippet. Ad visibility may also depend on site approval, visitor region, available campaigns, or ad blockers.

Placement & size guide

  • Top banner: appears below the site header on every public page. Use 970 × 90 px desktop; 320 × 100 px mobile.
  • Trending section: appears under the Trending heading, before its video cards on the home page. Use a 300 × 250 px rectangle, max 336 × 280 px.
  • After 12 videos: appears in All Videos after row 4 on desktop (and after 12 cards on mobile). Use a 300 × 250 px rectangle, max 336 × 280 px.
  • Video page ad: appears directly under the player. Use an Adsterra responsive banner, or paste the complete TSVideoShorts div + script snippet here to show its video ad widget on video pages.
  • Bottom banner: appears at the end of each public page. Leave its code empty to reuse the top banner; otherwise use the same responsive banner sizes.
  • Social Ads Bar: its Adsterra code is loaded on every public page, including video pages. Adsterra controls the bar's overlay position and behavior; paste its Social Bar code only in this slot.

Desktop/PC creative is used at 721 px and wider; mobile creative is used at 720 px and narrower. Resizing the browser switches the displayed version. Use responsive provider code when available. Image URLs are scaled to fit their placement. Ads may not fill if the provider blocks embedding, the ad blocker is on, or the provider has no available ad.

SECURITY

Realtime Database rules

Replace YOUR_ADMIN_UID with your administrator’s Firebase Authentication UID in these rules. Public visitors can query published videos / enabled categories, increment published video views, and use the limited Like and Comment features.

{
  "rules": {
    "videos": {
      ".indexOn": ["status"],
      ".read": "(auth != null && auth.uid == 'YOUR_ADMIN_UID') || (query.orderByChild == 'status' && query.equalTo == 'published')",
      "$videoId": {
        ".write": "auth != null && auth.uid == 'YOUR_ADMIN_UID'",
        "views": {
          ".read": "data.parent().child('status').val() == 'published' || (auth != null && auth.uid == 'YOUR_ADMIN_UID')",
          ".write": "data.parent().child('status').val() == 'published' && newData.isNumber() && newData.val() == (data.val() == null ? 1 : data.val() + 1)",
          ".validate": "newData.isNumber()"
        }
      }
    },
    "categories": {
      ".indexOn": ["status"],
      ".read": "(auth != null && auth.uid == 'YOUR_ADMIN_UID') || (query.orderByChild == 'status' && query.equalTo == 'enabled')",
      "$categoryId": {
        ".write": "auth != null && auth.uid == 'YOUR_ADMIN_UID'"
      }
    },
    "settings": {
      ".read": true,
      ".write": "auth != null && auth.uid == 'YOUR_ADMIN_UID'"
    },
    "connectionSignals": {
      "$uid": {
        ".read": "auth != null && auth.uid == $uid",
        ".write": "auth != null && auth.uid == $uid"
      }
    },
    "engagement": {
      "$videoId": {
        ".read": "root.child('videos').child($videoId).child('status').val() == 'published'",
        "likes": {
          "$visitorId": {
            ".write": "root.child('videos').child($videoId).child('status').val() == 'published' && ((!data.exists() && newData.val() == true) || (data.val() == true && !newData.exists()))",
            ".validate": "newData.val() == true"
          }
        },
        "comments": {
          "$commentId": {
            ".write": "root.child('videos').child($videoId).child('status').val() == 'published' && !data.exists() && newData.hasChildren(['name', 'text', 'createdAt'])",
            ".validate": "newData.hasChildren(['name', 'text', 'createdAt'])",
            "name": { ".validate": "newData.isString() && newData.val().length <= 40" },
            "text": { ".validate": "newData.isString() && newData.val().length > 0 && newData.val().length <= 500" },
            "createdAt": { ".validate": "newData.isNumber()" },
            "$other": { ".validate": false }
          }
        }
      }
    }
  }
}

Paste this JSON into Realtime Database → Rules after replacing the UID. Keep the views child rule: it permits only a single +1 transaction on published videos; all other video and category writes require the admin UID. The engagement rules allow public Like toggles and comments limited to 40-character names and 500-character messages. The demo connection signal is written under connectionSignals/{admin UID}. Add the project’s web config and Realtime Database URL in script.js.
